## 这次验证额外查出的三件事

### 1. 480P 的有效像素与名义宽高不一致（重要）

```
名义 864 × 480 = 414,720 px → 推算 49,005 tokens
实测 5 秒 480p   =              50,638 tokens
反推有效像素     = 428,544 px（= 864 × 496）
```

**按名义值报价会系统性少收 3.3%。** 已把 `SEEDANCE_EFFECTIVE_PIXELS` 的 480P
改为实测反推值，并加了单测锁住。

这一条只有真跑才能发现——公式在 720P 上精确成立，很容易让人以为它在其他分辨率也准。

### 2. 10 秒不是 5 秒的两倍

计费 token 数 = `有效像素 × (秒 × 24 + 1) ÷ 1024`。

- 5 秒 → 121 帧
- 10 秒 → **241 帧**（不是 242）

所以 10 秒是 216,900 tokens / **¥9.98**，而非早先按倍数外推的 217,800 / ¥10.02（偏高 0.4%）。
文件《积分与会员模型.md》已更正；5 秒数值不变，故积分表未动。

### 3. 平台会拒绝含真人肖像的输入图

第一次真跑被内容审核拦下（**未产生费用**）：

```
InputImageSensitiveContentDetected.PrivacyInformation
"the input image 'content[1]' may contain real person"
```

用的是本项目自己生成的参考图。这说明 **ARK 侧有真人隐私检测**，
用户上传的参考图可能被拒。对产品的含义：

- 流程必须能优雅处理这个错误码，不能崩在提交阶段
- 参考图生成环节应尽量避开明显的真人肖像特征
- 失败发生在生成之前，**不计费**（已实测确认）

已列入后续待办（含在服务端优雅处理该错误码）。
