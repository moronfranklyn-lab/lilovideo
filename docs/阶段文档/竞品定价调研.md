## 2. 两个关键发现

### 发现一：Seedance 2.0 处于价格带高端

| 模型 | 每秒价格 |
| --- | ---: |
| `vidu/viduq2-pro-digital-human` | $0.0050 |
| 中位数 | $0.0710 |
| `kling/kling-v3-t2v` | $0.0672–0.3360 |
| `google/veo-3.1-lite-t2v` | $0.0450–0.0720 |
| **`bytedance/seedance-2.0-t2v`** | **$0.0700–0.7800** |

Seedance 2.0 的价格**跨度是全部 112 个模型中最大的（11.1 倍）**，
且低端就等于行业中位数、高端接近中位数的 11 倍。

**这意味着**：我们选了一个**偏贵的模型**。它是你指定的，画质好，
但积分定价必须正视"基础成本高于多数竞品"这个事实。

### 发现二：毛利率的结论曾经是错的（已更正）

| 平台 | 公司侧成本（5 秒） | 订阅价 | 折算毛利 |
| --- | ---: | ---: | ---: |
| 可灵（专业档） | ~$0.30 | $32.56/3000 积分 | **约 80%** |
| Runway（Gen-4.5） | ~$0.60 | $28/2250 积分 | **约 79%** |
| **本产品（K = 1.4，官方公式）** | ¥4.97 | ¥0.35/积分 | **79.6%** |

**本节原先的结论是「行业 79–82%，我们只有 71.4%，偏低 8–10 个点，应把 K 提到 1.8–2.0」。
这个结论已撤回——71.4% 本身就是算错的。**

实付倍数是 `2.5K²` 而不是 `2.5K`（K 在积分数量与积分单价里各出现一次），
K = 1.4 的正确毛利是 **79.6%**，**本来就在行业区间内**。详见《积分与会员模型.md》§2.4。

**处置**：K 保持 1.4，不提价。相应地从下一节"做错的"里移出。

> 这个错误的教训比数字本身重要：它一路传进了本节的「建议的调整」表，
> 差点让产品为一个**根本不存在的**毛利缺口涨价 8–10 个点。
> 上游一个常数代错，下游所有推论都会一致地错，靠内部一致性查不出来。

## 3. 与竞品相比，我们做对和做错的地方

### 做对的

| 项 | 说明 |
| --- | --- |
| **积分不过期** | 可灵月度积分作废、Runway 仅 Max 可滚存。我们没有过期，对用户更友好 |
| **单张图重做不涨价** | 鼓励用户改到满意。可灵明确"失败也扣积分且无退款政策" |
| **先出样片** | 竞品没有这个机制。它们按次扣费，"生成废了"的成本由用户承担 |

> 竞品文档里有一句原话印证了我们的判断：
> 「计费按**生成次数**，不是按**可用片段**。一个 5 秒片段 60 积分；
> 一个你真正发出去的 5 秒片段，是 60 积分乘以试了几次。」
> **我们的「先出样片」正是针对这一点设计的。**

### 做错的

| 项 | 说明 |
| --- | --- |
| ~~**毛利定低了**~~ | **已撤回**：那是算式错误，实际毛利 79.6% 就在行业区间内，见上文「发现二」 |
| **免费额度给得少** | 可灵每日 66 积分（月度约 2,000）、Runway 一次性 125。我们一次性 300，够一次最小闭环但改不了几次 |
| **未提供年付** | 可灵年付省 34%、Runway 年付省约 20%。我们没有年付档 |
| **未按分辨率分档** | 竞品普遍 720P/1080P 差 33–50%。**已于《积分换算表.md》解决**：现在按分辨率与音轨共 29 个档位明码计价，用户可降档省钱 |

## 4. 曾经的数据矛盾（**已解决**）

本节记录的是一个**当时未解决**的矛盾，现已查清，过程值得保留。

| 来源 | 5 秒片段成本 | 推算依据 |
| --- | --- | --- |
| 当时的定价文档 | **¥7.10** | 把媒体口径「15 秒耗 30.888 万 tokens」误当作 5 秒的用量 |
| 当时的另一种推法 | **约 ¥14** | 同上口径再按官方 46 元/百万 折算 |

**两个数字都错，而且错在同一处**：都直接采信了一个二手媒体口径，没有去查真实调用。

**已核实的结果**——查询真实完成的 Seedance 任务，响应体含：

```json
"usage": { "completion_tokens": 108900 },
"duration": 5, "resolution": "720p", "framespacing": 24
```

即 **5 秒 720P = 108,900 tokens**（实际计费值），按 46 元/百万 = **¥5.01**。

**注**：方舟控制台价目页后来给出了官方公式
`Token用量 = 宽 × 高 × 帧率 × 时长 ÷ 1024`（帧率 24），据此 5 秒 720P 是
**108,000 tokens = ¥4.97**。实测比官方公式高 0.83%。报价统一以官方公式为准，
实测值作为交叉验证保留。《积分与会员模型.md》§2.5 记录了这次更正。

| 时长 | tokens | 成本 |
| --- | ---: | ---: |
| 5 秒 | 108,000 | **¥4.97** |
| 10 秒 | 216,000 | **¥9.94** |

> 数值以方舟控制台价目页的官方公式为准；实测为 108,900（+0.83%）。

**因此积分消耗值不需要翻倍，积分卡与会员价格也无需重定**——
与本文档 §4 原先担心的方向相反，实际成本比当时的估计**更低**。

> **教训**：成本数字不能从二手口径推算，必须查真实调用的 `usage` 字段。
> 这次修正使成本比旧值下降 29%。现已把实测依据写进
> `src/backend/models/pricing.py`，并由单测锁住那条 token 公式。

## 5. 建议的调整

在核实成本之后，建议按下列方向调整：

| 项 | 现状 | 建议 |
| --- | --- | --- |
| 收费倍率 K | 1.4（**毛利 79.6%**，已在行业 79–82% 内） | ~~提到 1.8–2.0~~ **不提，保持 1.4**（原建议基于算错的 71.4%） |
| 积分卡 | 无年付 | 增加年付档，约 8 折 |
| 视频计价 | ~~单一档~~ **已做** | 已按模型 × 分辨率 × 音轨拆成 29 个档位明码计价，见《积分换算表.md》 |
| 免费额度 | 一次性 300 | 可考虑**每日赠送少量**（如每日 20 积分，月度约 600） |
| 模型选择 | ~~只有 Seedance 2.0~~ **已做** | 已扩到 14 个模型 / 29 个档位，最低 10 积分（wan2.6-i2v-flash 无声），见《积分换算表.md》 |
