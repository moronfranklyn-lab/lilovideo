## 1. 本阶段目标

让后端具备真实生成能力，并跑通一条完整的 1 分钟成片，产出全部中间产物。

**通过条件**：证据包已交付，且阶段闸门是否表全部为"是"（无 Key 时可写"待验"的项除外）。

## 3. 技术方案

### 3.1 运行时

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| Python | 3.12.14 | 项目要求 >= 3.10，系统自带 3.9.6 不满足 |
| 获取方式 | uv 下载到外接盘 | 不需要管理员权限，不占用内置磁盘 |
| Python 位置 | `tools/uv-python/cpython-3.12-macos-aarch64-none/` | 外接磁盘 |
| 虚拟环境 | `src/backend/.venv` | 随项目，外接磁盘 |
| 依赖管理 | uv pip | 缓存目录设在外接盘 `tools/uv-cache` |

**为什么把工具链装在外接磁盘**：产品负责人的内置磁盘空间紧张。uv、Python、缓存、虚拟环境全部指向外接盘，避免占用内置磁盘。

### 3.2 模型选型

| 用途 | 模型 | 平台 | 配置字段 |
| --- | --- | --- | --- |
| 视频生成 | Seedance 2.0（`doubao-seedance-2-0-260128`） | 火山方舟 ARK | `ark.api_key` |
| 图像生成 | 待定，建议 Seedream 系列 | 火山方舟 ARK | `ark.api_key` |
| 语言模型 | 待定 | 待定 | 视选择而定 |

**关于 Seedance 2.5**：后端现有模型注册表只包含 2.0、2.0 Fast、1.0 Pro、1.0 Lite，不包含 2.5。若 2.5 确实可用，需要先确认官方 Model ID 并评估是否需要适配；本阶段先用 2.0。

### 3.3 成片规格

| 项目 | 规格 |
| --- | --- |
| 集数 | 1 集 |
| 镜头数 | 6 到 8 个 |
| 时长 | 约 1 分钟 |
| 画面比例 | 待确认（横屏 16:9 / 竖屏 9:16） |

### 3.4 质量硬底线

以下问题绝对不能出现在成片里：

- 角色在不同镜头里长相、穿着不一致
- 画面内容与剧情不符
- 画面出现明显错误（多余肢体、文字乱码）

这项约束决定后续"重做"机制要做多严格，也决定验收时如何判断。

## 5. 验收方式

产品负责人按以下步骤自行核对：

1. 打开 `http://localhost:8000/api/health`，看到服务正常返回。
2. 打开 `http://localhost:3000`，能看到后端数据。
3. 确认产物目录下存在成片文件，能直接播放。
4. 逐条核对第 3.4 节的质量硬底线。

## 8. 风险与阻塞

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 无火山方舟 ARK Key | 无法真实预跑，本阶段无法完成 | 产品负责人申请后填入配置 |

| Seedance 2.0 与图像模型风格不匹配 | 成片质量不达标 | 预跑后按实际效果调整模型组合 |
