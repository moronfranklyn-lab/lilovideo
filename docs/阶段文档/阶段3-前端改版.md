## 3. 技术方案

### 3.1 主题切换的实现路径（关键技术决策）

**发现**：Tailwind v4 把颜色类编译成 CSS 变量引用，而非硬编码色值。

```css
.bg-gray-100 { background-color: var(--color-gray-100) }
```

产物中同时存在 Tailwind 默认值与项目自定义值，后者在 `:root`，位于 `@layer` 之外，**层优先级更高**，因此胜出。

**结论**：只需重定义 `:root` 的基础层变量，62 处硬编码的 Tailwind 色类会全局变为暗色，**无需修改任何 tsx 文件**。

这比逐文件替换类的成本低一个量级，是本子阶段能快速完成的前提。

### 3.2 色阶反轉的方向约定

亮色主题下背景取低号色阶、文字取高号色阶。暗色主题必须**整体反转**：

| 用法 | 原值 | 新值 |
| --- | --- | --- |
| `bg-white`（表面） | `#ffffff` | `#1b1b23` |
| `bg-gray-25/50`（页面底） | `#fcfcfc` / `#fafafa` | `#0d0d12` / `#101015` |
| `border-gray-200` | `#eeeeee` | `#2b2b36` |
| `text-gray-700`（主文字） | 深灰 | `#d2d2dd` |
| `text-gray-500`（弱化） | 中灰 | `#6e6e80` |

**约定**：反转后**低号 = 暗、高号 = 亮**。修改色阶时必须保持这个方向，否则会出现「深色文字落在深色背景上」。该约定已写入 `globals.css` 的注释。

### 3.3 语义层的两处显式翻转

语义层不能完全依赖基础层自动跟随，有两处必须显式指定：

| Token | 原指向 | 暗色下的问题 | 处理 |
| --- | --- | --- | --- |
| `--lp-text-inverse` | `white` | 它用于浅色块上的文字，暗色主题下 `white` 已变暗，会不可读 | 显式改为 `#0d0d12` |
| `--lp-action-primary` | `black-soft` | 近黑在暗底上不可见 | 改用强调色 `#ff7a45` |

### 3.4 强调色选择

选定暖橙 `#ff7a45`。理由：

- 品红紫是 Pika 的品牌资产，直接抄既是模仿，也偏「娱乐型」
- 蓝色在暗底上偏冷，容易读成运维后台
- 暖橙在暗底上足够跳，语义接近「创作」，且与多数生成画面的色调不冲突

**使用纪律**：只允许出现在主操作按钮、当前选中项、焦点描边三处。

### 3.5 禁用态的处理（踩坑记录）

**问题**：主操作按钮禁用时，新用户看到的是一个近乎不可见的暗块，会误以为产品不可用。

**排查过程**：tsx 里的类名正确，但计算值不变。原因是一条手写规则覆盖了它：

```css
.lilo-action-primary:disabled {
    background: var(--lp-surface-soft) !important;
```

该规则在 `@layer components` 中使用 `!important`，压过了 tsx 里的工具类。

**修复**：拆开原本合并的禁用态规则。主操作保留强调色的弱化填充，次要操作与上传按钮正常淡出。

**对比度实测**：

| 状态 | 修复前 | 修复后 |
| --- | --- | --- |
| 主操作禁用态 | 2.17:1（不可读） | **6.37:1（AAA）** |

### 3.6 交互状态补全（参考 uiverse.io）

排查发现主按钮**只有 default / hover / disabled 三态**，缺两个关键状态：

| 缺失 | 影响 | 补法 |
| --- | --- | --- |
| `:active` 按下反馈 | 用户得不到「确实点到了」的确定性，易连点 | `translateY(1px)` + 更深的 `--lp-accent-active` |
| `:focus-visible` 键盘焦点 | 键盘用户看不到焦点位置，属可访问性缺陷 | 2px 强调色焦点环，覆盖 a/button/input/textarea/select |

**焦点环的坑**：第一版只写了 `.lilo-action-*` 类选择器，测试发现**侧栏导航链接仍是浏览器默认的蓝色焦点环**（`rgb(0, 95, 204)`）。原因是选择器没有覆盖 `a` 元素。改为覆盖全部可聚焦元素后，Tab 走查 10 个元素全部为强调色（`rgb(255,122,69)`，2px）。

**验证方式**：用键盘 Tab 逐元素走查并读取 `getComputedStyle().outlineColor`，而非目测。
