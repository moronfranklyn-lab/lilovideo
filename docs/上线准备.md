# Lilovideo 上线准备

> 面向部署者的操作清单与架构说明。基于代码现状整理，2026-09-24。

## 一、架构与端口

| 层 | 技术 | 端口 | 入口 |
|---|---|---|---|
| 前端 | Next.js 16 (React 19, Tailwind v4, TS) | 3000 | `src/frontend` |
| 后端 | FastAPI（Python venv） | 8000 | `src/backend/api_server.py` |
| 模型 | 方舟/DashScope 等（config.yaml） | — | 后端直连 |

前端所有 `/api/*` 请求通过 `next.config.ts` 的 **rewrites 逐条代理**到后端。
**后端新增路由时必须同步在 `next.config.ts` 加一条代理**（文件内有注释提醒；曾因漏配 `/api/cost/*` 导致前端 404）。

## 二、启动方式

### 本地开发
```bash
./scripts/start-dev.sh      # 一键起后端(:8000) + 前端 dev(:3000)
```
日志：`/tmp/lilovideo-api.log`、`/tmp/lilovideo-web.log`
停止：`kill $(cat /tmp/lilovideo-api.pid) $(cat /tmp/lilovideo-web.pid)`

### 生产构建 + 运行
```bash
cd src/frontend && npm run build   # 生成 .next
./scripts/start-prod.sh            # 后端 + 前端 next start
```
首次搭建：
```bash
cd src/backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cd src/frontend && npm install
```

## 三、密钥与配置（上线安全，代码已内置两道防线，见 `src/backend/deployment.py`）

1. **环境变量优先**：线上密钥只放服务端环境变量，不写进可写的 `config.yaml`。映射：

| 环境变量 | 配置点 |
|---|---|
| `DASHSCOPE_API_KEY` | api_providers.dashscope.api_key |
| `ARK_API_KEY` | api_providers.ark.api_key |
| `OPENAI_API_KEY` | api_providers.openai.api_key |
| `GEMINI_API_KEY` | api_providers.gemini.api_key |
| `DEEPSEEK_API_KEY` | api_providers.deepseek.api_key |
| `KLING_ACCESS_KEY` / `KLING_SECRET_KEY` | api_providers.kling.* |

2. **公网自动禁写配置**：监听 `0.0.0.0` 时（public 模式）配置写接口自动 403，`base_url` 不可被外部篡改。本地回环（127.0.0.1）照常可改。

## 五、已知注意点

- 前端 dev 用 `--webpack` 更稳（README 提示 lightningcss 原生模块问题）；build 不受影响
- **ffmpeg 依赖**：后端视频拼接需要 ffmpeg。ffmpeg 由 `src/install.sh` 下载到 `src/backend/bin/`（evermeet 构建），`api_server.py` 启动时自动加入 PATH。**该二进制不随仓库分发**（单个约 77MB，进 git 历史无法回收）。注意 evermeet 提供的是 **x86_64** 构建（Apple Silicon 上经 Rosetta 运行）；换架构需换对应静态构建（https://evermeet.cx/ffmpeg/ 或 BtbN 构建），或系统安装后无需内置
- 后端配置含真实密钥时，启动真实任务会消耗对应模型配额/积分（本次链路验证消耗少量 TTS/图片配额）
- 任务产物目录：后端 `code/result/task/<task_id>/`，前端经 `/code/*` 代理直接访问；上线前确认静态产物通过反代/对象存储可访问
