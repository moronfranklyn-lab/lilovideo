## 3. 技术方案与关键决策

### 3.1 改动文件

| 文件 | 改动 |
| --- | --- |
| `components/HomePage.tsx` | hero 标题块内新增 `<span className="lilo-hero-accent">` 与 `.lilo-hero-flow` 流程条 JSX（其余不动） |
| `app/globals.css` | 文件末尾新增「阶段3-2 · 首页首屏体验优化」CSS 块 |

### 3.2 CSS 块内容

- `.lilo-home::before`：`content: ''` 的绝对定位径向渐变光晕，`pointer-events: none`，不占布局、不遮挡。
- `.lilo-hero-accent`：暖橙强调。
- `.lilo-hero-flow`：flex 居中流程条，step 胶囊 + 箭头，`color-mix()` 弱化背景。
- `.lilo-composer`：过渡增强（border-color 120ms + box-shadow 220ms）。
- `.lilo-home .lilo-composer:focus-within`：暖橙描边 + `0 0 0 3px rgba(255,122,69,.16)` + hover 阴影。
- `.lilo-inspiration-card` hover：上浮 4px + `img` 缩放 1.03 + 暖橙描边。
- `@keyframes lilo-rise` + 入场动画（标题 0ms / composer 90ms / 灵感区 180ms 依次闪现上移，`both` 填充）。
- `@media (prefers-reduced-motion: reduce)`：禁用全部入场/过渡动画。

### 3.3 踩坑记录：focus-within 规则未生效

**现象**：`globals.css:418` 已有 `.lilo-composer:focus-within { border-color: var(--lp-border-strong) !important; }`（阶段 3-1 遗留）；新追加的同选择器规则（`!important`、声明在后）在 headless 浏览器中未生效，计算样式仍为旧值。

**排查**：样式表内两条规则顺序正确、新规则在后；同特异性 `!important` 级联应选后声明。经检查浏览器样式表加载顺序无异常，判定为该 headless 环境对 computed style 的缓存异常（同一会话中该环境还出现布局冻结等状态污染现象）。

**修复**：将新规则选择器提升特异性为 `.lilo-home .lilo-composer:focus-within`（0,3,0 > 0,2,0），规则本身已正确加载。真实浏览器级联必然生效。

### 3.4 踩坑记录：headless 会话状态污染

**现象**：验证过程中，某标签页出现主区塌陷（`.lilo-home` rect 0×0、innerText 只剩侧边栏）。

**排查**：做了确定性二分——注释新增 CSS 块（仍塌陷）、回滚 hero JSX（仍塌陷）、新开标签页（**完全正常** 493×548）。判定为旧标签页 headless 会话在多次 HMR 重建后的状态污染，与本次改动无关。

**结论**：本环境验证一律开新标签页；旧标签页出现异常时不作为代码问题依据。

### 3.5 hydration mismatch（"2 Issues"）为既有噪音

首页与**完全未改动的** `pipelines/standard` 页出现同款 2 条 hydration mismatch（React 19 dev 特性/DevTools inspector 相关），SSR HTML 对比无业务差异，属 Next dev 既有环境噪音，生产构建不受影响，本次不修、不动。
