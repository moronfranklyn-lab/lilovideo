## 一、最值得参考：LibTV（同类产品的完整形态）

**网址**：https://www.liblib.tv/

**为什么最值得看**：它是国内**唯一一个同时面向人类和 Agent 设计的 AI 视频产品**，而且用"两个入口，一套底层能力"解决了专业用户与普通用户的冲突。这个结构与本产品的 PRD 高度一致。

### 可直接借鉴的三点

**1. 双入口结构**

| 入口 | 面向 | 形态 |
| --- | --- | --- |
| 无限画布 | 专业创作者 | 节点连线、参数调整、模型选择、摄像机控制 |
| Agent Skills | 普通用户 | 一句话触发，后端自行处理分镜、选模型、调参数 |

**对应到本产品**：同步工作台（个人创作者）+ 异步 API（企业客户）。PRD 里已经写了两者共用一套引擎，LibTV 证明了这条路走得通。

**2. 任务与项目打通**

Agent 每完成一个任务，**自动在画布里生成一个真实项目，节点全部串好**。用户可以在画布上继续加工。

**对应到本产品**：这就是"交付的不是一个 mp4，而是一整套可继续编辑的生产资产"的落地形态。我们的 `code/result/` 已经存了全部中间产物，差的是把它们组织成可继续编辑的结构。

**3. "Agent 出初稿，人类去画布上优化"**

原文的判断：不指望 Agent 一次给 100 分，给 70 分，人再手动优化到 100 分。

**这正是 7 个停点的设计依据**——在人能判断和修正的地方停下来。

### 一个可用的差异点

文章提到 LibTV **缺了 Seedance 2.0**（"现在几乎没有对外开放"）。

**而我们的后端已经跑通 Seedance 2.0**（实测任务 `cgt-20260922205545-rjrzl` 成功）。这是一个可以正经讲的产品差异点。

### 具体交互细节值得抄

- **脚本节点**：给一段剧本生成对应分镜脚本，或用"角色设定 + 一段话"生成分镜
- **摄像机控制**：把相机实物、镜头、光圈、焦距做成 UI（专业向，我们第一版不做）
- **图片处理**：高清、扩图、重绘、擦除、抠图、多角度、一键改光
- **网格切分**：四宫格剧情推演图可切分提取
- **`/` 命令唤起预设**：把高级功能藏在斜杠命令里，不占用主界面

## 二、设计系统参考（可直接落地为 token）

这两份是**从真实线上产品提取的设计系统**，包含具体的颜色值、字号阶梯、组件样式和"不要做什么"清单。比看截图有用得多。

### 2.1 Luma —— 极简编辑风（推荐方向）

**来源**：[design-bites/lumalabs.ai/DESIGN.md](https://github.com/educlopez/design-bites/blob/main/design-mds/lumalabs.ai/DESIGN.md)

**核心特征**：整个系统**没有任何品牌色**，只有灰阶 + 一个用于危险操作的红色。

| 项目 | 值 |
| --- | --- |
| 页面背景 | `oklch(100% 0 0)` 纯白 |
| 正文 | `oklch(14.5% 0 0)` 近黑 |
| 边框 | `oklch(92.2% 0 0)` 发丝级灰线 |
| 弱化背景 | `oklch(97% 0 0)` |
| 危险色（唯一彩色） | `oklch(57.7% 0.245 27.325)` |

**排版**：只用两个字重（400 / 500），标题按字号比例收紧字距（约 −5%），正文 16/24。

**深度**：**完全不用阴影**，靠明暗对比和硬边界制造层次。

**为什么适合我们**：产品主体是 AI 生成的画面，**界面越安静，画面越突出**。这与"让内容提供所有颜色"的思路一致。

**要注意的**：这份参考是**营销落地页**，不是工作台。工作台的信息密度更高，直接照搬会太空。要取的是它的克制与 token 体系，不是它的留白比例。

### 2.2 Pika —— 高能暗色风

**来源**：[design-ai/pika/DESIGN.md](https://github.com/Khalidabdi1/design-ai/blob/main/design-md/pika/DESIGN.md)

**核心特征**：近黑底 + 品红到紫的渐变品牌色，胶囊形控件，视频卡片优先。

| 项目 | 值 |
| --- | --- |
| 页面背景 | `#0A0A0F` |
| 卡片面 | `#141420` |
| 品牌渐变 | `#E040FB` → `#7B2FBE` |
| 边框 | `#2A2A40` |
| 主文字 | `#F2F2FF` |
| 次要文字 | `#8B8BAA` |

**组件模式**（值得抄的具体做法）：

- **生成按钮**：胶囊形 + 品牌渐变填充
- **提示词输入框**：胶囊形、深色、聚焦时品红描边 + 光晕
- **视频卡片**：16:9 比例、hover 时上浮 2px + 品红描边发光
- **生成进度条**：3px 高的渐变进度条
- **风格预设 chip**：胶囊形，选中态为品红描边 + 半透明填充

**为什么可选**：这套更适合"C 端娱乐型"产品。如果要走**创作者工具**路线，Luma 的克制更合适；如果要走**消费级**路线，Pika 的活力更有效。

**能直接抄的**：进度条、风格 chip、卡片 hover 这三套组件模式，风格中性、两边都能用。

## 四、UIverse 组件库评估（https://uiverse.io/buttons）

**结论先行：这个站的按钮绝大多数不适合本产品，但有两个交互细节值得取。**

站点共 **2012 个按钮**，绝大多数是装饰性/动效展示型作品。对本产品的价值不在"拿来即用"，而在**验证我们缺了哪些交互状态**。

### 4.1 采纳的两点

| 采纳项 | 来源 | 我们原本的状态 | 改进后 |
| --- | --- | --- | --- |
| **按下反馈** | 参考 [modern-dragon-25](https://uiverse.io/JasonMep/modern-dragon-25) 的下沉思路 | 全局 `:active` **0 处** | 按下时 `translateY(1px)` + 用更深的 `--lp-accent-active` |
| **键盘焦点环** | 参考 [mean-bird-62](https://uiverse.io/MuhammadHasann/mean-bird-62) 的可见焦点处理 | 全局 `:focus-visible` **0 处**，键盘用户只能看到浏览器默认蓝环 | 统一为 2px 强调色焦点环，覆盖 `a/button/input/textarea/select` |

> **为什么这两点重要**：主按钮按下时没有任何反馈，用户得不到"确实点到了"的确定性；键盘焦点不可见则是实打实的可访问性缺陷，不只是观感问题。

**实现细节上的取舍**：modern-dragon-25 用的是硬边 3D 投影（`box-shadow: 0 6px 0`），与本站的克制基调冲突，因此**只取"按下下沉"的思路**，改为 1px 位移的轻反馈。

### 4.2 明确不采纳

| 不采纳 | 代表作品 | 原因 |
| --- | --- | --- |
| 彩虹渐变背景 | plastic-quail-42 | 与"单一强调色、界面安静"的立场直接冲突；且会与生成画面抢颜色 |
| 硬边 3D 立体投影 | modern-dragon-25 | 偏卡通厚重，不适合创作者工具 |
| 逐字翻转变形 | tall-goose-46 | 装饰性强，会干扰阅读 |
| 新粗野主义阴影 | modern-husky-6 | 视觉噪音大 |
| 多层光晕胶囊 | mean-bird-62 | 作为主按钮过重；仅取其焦点处理思路 |

### 4.3 对这类站的判断

**"好上手"的核心是把用户引向正确的第一步，以及让系统状态清晰可见，而不是按钮外观。** 装饰性组件库解决的是"按钮好不好看"，而我们的问题在"用户知不知道该点哪里、点完发生了什么"。

因此本产品对组件库的使用原则：

1. **只取交互状态与反馈机制**，不取视觉装饰
2. 任何引入的样式必须能用现有的 token 体系表达，否则不引入
3. 引入前先确认它解决的是真实缺陷，而不是"看起来更花哨"

## 五、给本产品的建议方向

综合以上，本产品采用 **暗色 + 单一暖橙强调色**：

| 层面 | 取谁 | 理由 |
| --- | --- | --- |
| 色彩体系 | Luma | 无品牌色、纯灰阶，让 AI 生成的画面成为唯一的颜色来源 |
| 字体与层级 | Luma | 两个字重 + 负字距，靠字号而非字重建立层级 |
| 深度与阴影 | Luma | 不用阴影，靠边框和明暗分区 |
| 进度条 / chip / 卡片 hover | Pika | 这三套组件模式成熟且风格中性 |
| 布局密度 | 自定 | 工作台比落地页需要更高信息密度，不能照搬留白 |

**方向已确认：消费级好上手路线。** 落地标准见《前端设计规范.md》，已实施于阶段 3 第 1 子阶段。
