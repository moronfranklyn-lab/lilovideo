# 样片模式：先出样片，确认后再批量生成

| 项目 | 内容 |
| --- | --- |
| 状态 | **后端完成**，前端交互待接 |
| 完成日期 | 2026-09-22 |
| 产品决策 | 默认先出样片，**用户可跳过** |

---

## 1. 为什么做这个

视频按时长计费。实测与官方定价：

| 环节 | 成本 | 耗时 |
| --- | --- | --- |
| 剧本生成 | 极低 | 87 秒 |
| 角色与场景设计 | 低 | 50 秒 |
| 分镜规划 | 极低 | 43 秒 |
| **参考图生成** | **低** | 123 秒 |
| **视频生成** | **约 1 元/秒** | **5 秒片段需 259 秒** |

问题在于**成本分布极度不均**：参考图阶段很便宜，视频阶段很贵。而现在的做法是
**视频全部批量生成后，用户才第一次看到动态效果**。如果风格不对，返工的是整片。

算一笔账：6 个镜头 × 10 秒 = 60 秒视频，约 60 元。
若全部生成后才发现不对，这 60 元就白花了。

**样片模式把验证点前移**：先花 5 元生成 1 个 5 秒片段，确认效果后再生成其余。

---

## 2. 交互设计

### 用户可选（产品决策）

| 选择 | 行为 | 适合谁 |
| --- | --- | --- |
| **先出样片**（默认） | 只生成首个片段，5 秒 | 新手、不确定风格是否合适 |
| 直接生成全片 | 一次生成全部片段 | 熟手、已确认过风格 |

**为什么默认样片**：新用户最怕"花了一笔钱拿到不满意的东西"。默认保护他，
而熟手只需一次点击就能跳过，不被拖慢。

### 流程

```
参考图阶段完成（成本很低）
    ↓
用户选择：
  ├─ 先出样片 ──→ 生成 1 个片段（5 秒，约 5 元）
  │                  ↓
  │              用户看到动态效果
  │                  ├─ 满意 → 生成其余片段
  │                  └─ 不满意 → 改提示词重做样片（再约 5 元）
  │
  └─ 直接全片 ──→ 一次生成全部
    ↓
后期剪辑 → 成片
```

**关键收益**：最坏情况下，用户发现风格不对只花了 5 元，而不是 60 元。

## 3. 实现

### 触发方式

介入参数 `generate_preview`：

```json
POST /api/project/{session_id}/intervene
{ "stage": "video_generation", "modifications": { "generate_preview": true } }
```

### 改动点

改动刻意做得很小——**只在生成目标选择处裁剪**，不动调用链：

| 位置 | 改动 |
| --- | --- |
| `video_agent.py` 常量 | 新增 `PREVIEW_CLIP_SECONDS = 5` |
| `video_agent.py` `run()` 前 | 判定 `preview_only`，把目标列表裁成首个片段 |
| `video_agent.py` 时长处 | 样片模式用固定 5 秒，而非分镜的 `total_duration` |
| `video_agent.py` 返回处 | 附 `preview` 状态，告知剩余片段数 |

### 返回结构

```json
{
  "payload": { "session_id": "...", "clips": [...] },
  "stage_completed": true,
  "preview": {
    "preview_only": true,
    "preview_seconds": 5,
    "generated": 1,
    "total": 6,
    "remaining": 5
  }
}
```

前端据此显示「样片已完成，还有 5 个片段未生成」与「生成其余片段」按钮。

## 4. 两个容易写错的细节

### 细节一：样片时长必须用固定值，不能用分镜时长

分镜里每个片段是 10 秒。若直接沿用，样片就变成 10 元而非 5 元，省成本的意义减半。
因此样片模式**显式覆盖**为 `PREVIEW_CLIP_SECONDS`。

### 细节二：索引必须仍指向原始片段列表

首尾帧生视频模式靠 `seg_index` 取「下一个片段的参考图」作尾帧。
若在裁剪后的列表里枚举，索引会错位，**尾帧会取错**。

实现上注意：循环用裁剪后的列表，但 `seg_index` 取**原始列表的索引**。
测试 `test_样片模式下索引仍指向原始列表` 专门守住这一点。

---

## 5. 为什么没走"按项重做"分支

orchestrator 在判定为「按项重做」时（`regenerate_clips`）会走合并分支重建 payload，
那可能丢掉 `preview` 标记。

`generate_preview` **不**满足该判定，因此走正常执行路径，标记得以保留。
测试 `test_generate_preview_不被判为按项重做` 守住这个性质，
另有回归测试确保 `regenerate_clips` 的原有行为未被破坏。
