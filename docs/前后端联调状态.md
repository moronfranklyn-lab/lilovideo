## 3. 本次查出并修复的问题

### 前端代理漏配 `/api/cost/*`

**症状**：成本接口直连后端正常，经前端访问返回 404。

| 路径 | 直连后端 | 经前端代理 |
| --- | --- | --- |
| `/api/cost/pricing` | 200 | **404** |

**原因**：`next.config.ts` 的 `rewrites` 是**逐条列举路径**的，不是通配。
后端新增 `/api/cost/*` 后，前端不会自动跟上。

**为什么危险**：这个 404 看起来像后端故障，排查时容易误判方向。

**修复**：补上 `/api/cost/:path*` 与 `/api/health`，并在配置里加了注释提醒同步维护。

**顺带做了系统核对**：把后端全部 13 个 API 前缀与代理覆盖逐一对比，现已全部覆盖。

## 4. 仍未接通的部分（重要）

### 成本核算

后端已具备（定价表、成本计算、会话记录、三个接口），**前端完全没有调用**：

| 后端接口 | 前端调用 |
| --- | --- |
| `GET /api/cost/pricing` | **无** |
| `POST /api/cost/estimate` | **无** |
| `GET /api/cost/session/{id}` | **无** |

也就是说：**「生成前报价」与「实时费用累加」在界面上都看不到。**

这直接违背 PRD 里「成本必须可见」这条判断——用户目前无法在生成前知道要花多少钱。

### 样片模式

后端已具备（`generate_preview` → 只生成 1 个 5 秒片段，成本从最坏 60 元降到 5 元），
但前端**不处理 `preview` 返回字段，也没有「先看样片 / 直接生成全片」的选择入口**。

按产品负责人的决策，该项默认应为「**先出样片，用户可跳过**」——
目前这个默认行为在界面上不存在，只能通过 API 手工传参。

### 成本未串联进生成流程

`cost_store.record_usage` 已实现并有测试覆盖，但**还没有在 orchestrator 的阶段执行里被调用**。
所以即使前端接上查询接口，查到的也会是空记录。

**这三项是同一件事的三个环节，缺任何一环成本功能都不成立：**
```
记录用量（后端 orchestrator） → 查询接口（已通） → 界面展示（前端缺失）
        ↑ 缺失                                        ↑ 缺失
```

---

## 5. 建议的下一步顺序

1. **在 orchestrator 里调用 `cost_store.record_usage`** —— 否则后面两步都没有数据
2. **前端加成本展示** —— 生成前报价 + 进行中累加 + 结束时总额
3. **前端加样片模式选择** —— 视频阶段提供「先看 5 秒样片 / 直接生成全片」
