# 图标设计 · 门缝方向

> 本轮按 GitHub skill [krrish-skills / logo-designer](https://github.com/nkrrish/krrish-skills)
> 的流程重做。该 skill 的核心价值不是"更好的画法"，而是**把质量判断变成可测量的检查**。

---

## 1. 为什么重做

第一版我即兴画了四个几何方案，用户反馈"有点难看"。回溯原因是两条，都是 SKILL 明确警告过的：

| 问题 | SKILL 的对应条款 |
| --- | --- |
| 内嵌 `#1B1B23` 背景底板 | **绝不要把背景底板烘焙进图标**。每个空隙必须是真正的洞，否则单色渲染时塌成实心方块 |
| "播放符 + 右上点子" | AI 领域**禁用** sparkle、四角星。且播放键/相机是 AI 视频类最饱和的符号，能说出三个产品在用即不具独有性 |

审计工具对第一版的实测：

```
lilovideo-icon.svg     INK 0.961  →  FAIL 墨迹0.96>0.85(疑似底板)
```

**0.961 就是"烘焙了底板"的实锤**，这个问题在 SVG 源码里看不出来，在像素上一眼可见。

## 2. 选定的方向

**种子（用户在五个候选中选定）**：门缝 —— 一帧是一个完整的世界，让静止变成影片的是其中一道开口。

**谱系**：日本纹章（Kamon）主导。该谱系要求「负空间是主要材料」「实心块与等重的白色切口」「没有细线、没有偶然」。

**为什么不用播放键**：播放符与相机是 AI 视频类最饱和的符号。按 SKILL 的测试——"如果你能说出三个在用这个标志的产品，它就不归你"——播放键不通过。

## 3. 候选与审计结果

| # | 名称 | 谱系 | 审计 | 判断 |
| --- | --- | --- | --- | --- |
| 01 | 斜缝 | 日本纹章 | INK 0.46 · RGN 1→1 · THIN 3.00 | **推荐基础** |
| 01b | 斜缝（缝里有光） | 日本纹章 | INK 0.44 · RGN 2→2 · THIN 3.00 | **推荐**，见下 |
| 02 | 缺口 | 日本纹章 | **FAIL 笔画 0.38px@16** | 30px 下会消失，需改实心构造 |
| 03 | 环缝 | 日本纹章 | INK 0.26 · RGN 1→1 | 可用，但偏 generic |
| 04 | 断轴 | 构成主义 | INK 0.25 · RGN 2→2 | 太散，两半各管各的 |
| 05 | 步进 | 欧普 / 系统性重复 | INK 0.20 · RGN 6→6 | **不建议**：读起来像柱状图/均衡器，对视频产品是错误语义 |

### 01 与 01b 的差别

01 是全图同一个橙色实心块，按 SKILL 的说法**完美对称是惰性的**，因此没有重心、显得平。

01b 做了三件事：

1. **缝有方向**：上宽下窄、偏离中心，像一道正在被推开的门，而不是一道静止的刻痕
2. **缝里透光**：缝右侧一条更亮的窄面色（`#FFD9C2`），读作「门后透进来的光」，它是全图唯一焦点
3. **打破对称**：质量偏左，右侧留更大的空

单色版仍是完整实体（审计确认 RGN 保持 2→2，不会塌陷），因此进可两色、退可单色。

## 4. 审计工具

原版 `audit.sh` 依赖 ImageMagick，本机无法安装（无 brew，装它需管理员密码）。
`audit_icons.py` 用 **resvg（渲染）+ Pillow（分析）** 等价重实现，不放弃度量退回肉眼看。

| 指标 | 含义 | 阈值 |
| --- | --- | --- |
| `INK` | 墨迹覆盖率 | >0.85 判为烘焙底板 |
| `TPL` | 单色塌陷（alpha 标准差） | <3.0 判为塌成空白或实心 |
| `RGN` | 区域数 256px → 16px | 跌幅 >50% 判为 16px 镂空闭合 |
| `THIN` | 最细特征宽度折算到 16px | <0.65px 判为会消失 |
| `NODES` | path 命令数 | >90 判为描摹或过度雕琢 |
| 边界 | 渲染后像素 bbox 留白 | <3% 判为贴边会被圆角遮罩切到 |

```bash
python3 audit_icons.py threshold/
```

### 写工具时自己踩的两个坑

**坑一：边界检查误报全部图标。**
第一版直接对 SVG 全文抓数字，结果把颜色值（`#FF7A45` 里的 7 与 45）和 `stroke-width` 也当成坐标，五个图标全部误报"越出安全边距"。

**坑二：改用路径解析后仍然错。**
SVG 的圆弧命令参数包含与坐标同形的数字——`a8 8 0 0 1 -8 -8` 里的 `-8` 是**相对偏移**，不是绝对坐标。用正则无法区分，仍会误报。

**最终做法**：改用**渲染后的像素 bbox** 判定。像素是权威来源，不需要解析路径语法。测量代码自己出错比测不出更糟，所以这一点值得记下来。

## 5. 顺带发现：现有 logo 与本产品无关

`src/frontend/public/logo.jpg`（225×225）的内容是 **`Uni-MoE` 字样的绿/紫/蓝渐变图**（平均色 `rgb(182,213,192)`）。

这是上游项目所有者从别处带来的图片，与小云雀、与本产品都没有关系。**替换它没有任何损失。**

同时项目缺少 `favicon`。
