| 项目 | 内容 |
| --- | --- |
| 归属阶段 | 3 正式前端（产品能力子阶段） |

---

## 1. 目标

对应 PRD 里两条产品判断：

- **成本必须可见**：视频按秒计费，不可见的成本就是失控的成本
- **生成前要有报价**：用户在动手前知道大概要花多少

---

## 2. 设计原则

### 原则一：算不出来就说算不出来

这是整个框架最重要的一条。**"未知"与"免费"必须可区分。**

| 情况 | 返回 | 界面应显示 |
| --- | --- | --- |
| 模型未登记定价 | `None` | 成本未知 |
| 用量字段缺失 | `None` | 成本未知 |
| 定价已登记且用量完整 | 金额 | 具体金额 |
| 用占位价或换算价算出的 | 金额 + `verified: false` | 金额 + "可能不准"提示 |

**绝不返回 0 冒充。** 测试里有专门用例守住这条：`test_零用量返回None而不是零`、`test_未登记模型返回None而不是零`。

### 原则二：价格是外部事实，与计算逻辑分离

价格会变。因此：

- `models/pricing.py` 只存"当前已知值 + 来源 URL + 核实日期"
- `models/cost.py` 是纯函数，不硬编码任何价格
- 每条已核实的定价必须带 `source`，测试会校验这一点

### 原则三：成本记录不影响生成流程

写成本失败不能中断生成。`cost_store.record_usage` 默认吞掉异常并告警，
有测试 `test_成本目录不可写时不中断主流程` 守住。

### 未核实

| 模型 | 状态 | 说明 |
| --- | --- | --- |
| `doubao-seedance-2-0-fast-260128` | **未核实** | Fast 版官方定价未查到，暂按标准版占位。使用前必须核实。 |

## 4. 模块结构

```
models/
├── pricing.py     定价注册表（外部事实，带来源与核实标记）
├── cost.py        成本计算（纯函数，可单测）
└── cost_store.py  会话级记录与汇总（落盘，与工作流状态解耦）

api/routers/
└── cost.py        三个接口：查会话成本 / 生成前预估 / 查定价表
```

### 为什么成本单独落盘

写在 `code/data/sessions/<sid>.cost.json`，**不修改 orchestrator 持有的会话文件**。
这样成本记录与工作流状态解耦：成本写入失败也不会影响生成流程。

---

## 5. 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/cost/session/{session_id}` | 查累计花费，含按阶段、按模型分组 |
| `POST /api/cost/estimate` | 生成前预估：给定模型与时长，返回预估金额 |
| `GET /api/cost/pricing` | 查定价表与未核实清单 |

### 实测结果

```json
// GET /api/cost/estimate  {"model_id":"doubao-seedance-2-0-260128","seconds":10}
{
  "known": true,
  "amount": 10.0,
  "billing": "per_second_approx",
  "verified": false,
  "breakdown": "10 秒 × 约 1.0 元/秒（按官方 per-token 定价与实测 tokens 量折算，非账单级精度）"
}

// 未知模型
{ "known": false, "reason": "该模型未登记定价，或计费方式不支持按秒预估" }
```

会话汇总实测：写入两条用量后读回 `14.9285 元`，
按阶段分组 `{script_generation: 0.72, video_generation: 14.20848}`，计算正确。

## 6. 待接的部分（重要）

**框架已就绪，但真实用量还没接进模型客户端。**

现状：模型客户端只返回文本 / 路径 / URL，**不返回 usage**：

| 客户端 | 现在返回 | 需要改为 |
| --- | --- | --- |
| `llm_dashscope` / `llm_deepseek` 等 | 文本字符串 | 附带 usage |
| `image_seedream` | 图片路径列表 | 附带生成张数 |
| `video_seedance` | 视频 URL | 附带 tokens 用量 |

**好消息**：`video_seedance.py` 的 `_poll_until_done` 在任务成功时已经拿到了完整响应体
（含可能的 usage 字段），只是**只取了 video_url 就丢掉了其余字段**。改造成本不高。

**待验证项**：ARK 视频任务的成功响应里是否真的含 `usage` 字段。
实测时 ARK 接口出现 SSL 连接失败，未能取证。网络恢复后需确认；
若确实不含 usage，则视频成本只能用"秒数 × 换算单价"估算，并如实标记为未核实。

## 7. 测试

| 测试文件 | 用例数 | 覆盖 |
| --- | --- | --- |
| `tests/test_cost.py` | 14 | 各计费方式、缓存不重复计价、边界与异常输入 |
| `tests/test_cost_store.py` | 11 | 累计正确性、不可计算时跳过、文件损坏降级、写入失败不中断主流程 |

**全量测试：33 passed**（含原有 8 个安全测试）。

重点守住的边界：

- 零用量 → `None`（不是 0）
- 未登记模型 → `None`（不是 0）
- 缓存命中数大于输入总数 → 不产生负价格
- 成本文件损坏 → 降级为空，不抛异常
- 磁盘写入失败 → 吞掉异常，不影响生成
