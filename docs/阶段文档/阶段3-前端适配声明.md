## 1. 对需求的理解

**Lilovideo 是什么**：一个从一句话创意到成片的 AI 视频生产系统（6 阶段状态机：

剧本 → 角色 / 场景 → 分镜 → 参考图 → 视频 → 后期），单人使用、本地部署、10 秒级短片。

**前端要承担什么**：让用户在没有技术背景的前提下完成整条创作链路，并让

三个产品主张在界面上真实可见 ——



1. **成本必须可见**：生成前报价、进行中累加、余额 / 积分常驻；

2. **质量可控**：每个阶段可介入重做，视频可先出样片再批量生成；

3. **进度可感知**：7 个阶段的进度与状态全程中文化显示。

**验收标准**（对照 PRD 与项目进度）：



* 用户创建项目前能看到视频档位参考价（生成前报价）；

* 创作过程中顶部常驻本会话累计成本（进行中累加）；

* 侧边栏常驻积分余额，可展开查看账户与流水；

* 视频阶段提供「先出样片（5 秒）/ 生成其余片段」入口；

* 全部页面无内部字段名（`script_generation` 等）泄漏；

* 各页面在暗色主题下视觉可用。

## 2. 有没有多出未要求的花费・平台・范围

**没有新增任何外部花费或平台。** 本次前端改动全部消费既有的本地服务

（Next.js :3000 → FastAPI :8000），未引入新依赖、新模型、新密钥。

**一处超出 "纯前端" 范围的改动，已说明并修复**：



* 后端 `GET /api/sessions` 在 Deepseek 的成本验证文件（`verify_cost_wiring.cost.json`）

  写入会话目录后崩溃（`updated_at` 为 ISO 字符串与 float 混排，排序抛 `TypeError`）。

  该接口直接阻塞前端历史记录，已在 `orchestrator.py` 做日期类型规范化修复

  （兼容 `datetime` / `float` / ISO 字符串），**未删除任何验证文件**。

  这是为让前端功能成立而做的最小后端修复。

### 3.2 样片模式（PRD「先出样片，可跳过」）



| 状态          | 界面表现                                 | 行为                                                       |
| ----------- | ------------------------------------ | -------------------------------------------------------- |
| 视频阶段未生成任何片段 | 「先出样片，确认质量再批量生成」提示条 + 「先出样片（5 秒）」按钮  | 触发 `onIntervene({ generate_preview: true })`，后端只生成首段 5 秒 |
| 样片生成中       | 「正在生成样片（首个片段 5 秒）…」提示                | —                                                        |
| 样片完成、仍有剩余片段 | 「样片已完成（5 秒），还剩 N 个片段」+「生成其余 N 个片段」按钮 | 触发 `onRegenerate()` 重跑视频阶段，已生成片段自动跳过，补齐剩余后进入后期           |

> 注意：样片确认前请勿点「确认并继续」，否则会带着仅 1 个片段的视频进入后期；
> 提示条已用醒目样式与文案引导先「生成其余片段」。

## 5. 暂缓项与遗留（不影响阶段 3 验收）



| 项                     | 状态                                                                                                                  | 影响                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------ |
